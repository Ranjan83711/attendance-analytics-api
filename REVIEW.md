# REVIEW.md

Defects found in the starter `app/main.py`. Line numbers refer to the original starter file. Examples assume a
server running in UTC, which is how the grader and most containers run.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | module, `MongoClient(...)` L22 | Created without `tz_aware=True`, so PyMongo returns naive datetimes. Comparing them with aware datetimes raises `TypeError`, and naive values get serialized as if they were local time. | Any arithmetic between a stored `punch_in` and an aware "now" crashes, giving a 500. | `MongoClient(..., tz_aware=True, tzinfo=utc)`. Every datetime in the code is aware UTC. |
| 2 | `compute_late_minutes` L35 | The shift start is built with `punch_in.replace(hour, minute)`, which uses the punch's own time zone (UTC from the DB, or server-local time) instead of IST. | A punch at 09:45 IST (04:15Z) on a UTC server is compared with 09:30 **UTC**, so the result is 0 late minutes instead of 15. | Shift start = attendance date + `shift_start` in IST (`shift_moment`). |
| 3 | `compute_late_minutes` L37 | The grace check is `minutes > 10` on whole minutes, but R2 says strictly more than **10:00** (seconds matter). | 09:40:30 gives 10 whole minutes, which is not more than 10, so it returns 0. R2 expects 10. | Compare elapsed **seconds** with 600; when late, return `seconds // 60`. |
| 4 | `compute_late_minutes` L35 | Ignores overnight shifts. A punch after midnight belongs to the shift that started the previous evening. | Shift 22:00-06:00, punch at 00:30: the start becomes 22:00 the same day, so the difference is negative and it returns 0 instead of 150. | Late minutes are computed from the R1 attendance date (the day the shift started). |
| 5 | `compute_work_hours` L41 | `round(float, 2)` is binary floating point with round-half-even, not R4's half-up. | 1h 0m 18s = 1.005 h; `round(1.005, 2)` gives `1.0`, but R4 expects `1.01`. Near 4.50 this also flips `half_day` (R5). | `Decimal(seconds) / 3600` quantized with `ROUND_HALF_UP`. `half_day` compares the rounded Decimal. |
| 6 | `compute_overtime` L47 | No 30-minute minimum (R3). | Sample #1 punches out at 18:35 and gets 5. The data model says 0. | Return the minutes only when they are at least 30. |
| 7 | `compute_overtime` L46 | For overnight shifts the end is put on the start date, not the next day. | Shift 22:00-06:00, out at 06:40 the next morning gives **1480** instead of 40. | Add one day to `shift_end` when `shift_end <= shift_start`. |
| 8 | (all instants) | Instants are never truncated to whole seconds (R1). | 09:40:00.900 would count as 10:00.9 elapsed, and the stored/returned value keeps the milliseconds. | `from_ms` floors to the second before any calculation and before storing. |
| 9 | `EmployeeIn`, `PunchInIn` L53-66 | No validation: any `emp_code` / email / shift string, invalid `joined_on`, `shift_start == shift_end`. `punched_at` accepts seconds, floats, numeric strings and `true` (lax int). `status` accepts any string, including `ABSENT`. | `{"punched_at": 1783312500}` (seconds) creates a record dated 1970. `"status": "ABSENT"` is accepted at punch-in. | Pydantic constraints from openapi.yaml: `Strict` int with range [1e11, 4102444800000], `Literal` statuses, regex patterns, a real-date check, and a model validator for equal shift times. |
| 10 | `health` L73 | Always returns 200, even when MongoDB is down. | Stop Mongo: `/health` still says ok, and the runner starts testing against a dead DB. | `ping` MongoDB. On failure, return 503. |
| 11 | `create_employee` L79-83 | Check-then-insert with no unique index. Two concurrent creates both pass the check. | 10 parallel POSTs with the same `emp_code` create several documents. | Unique index on `emp_code`; insert and map `DuplicateKeyError` to 409. |
| 12 | `create_employee` L82, `list_employees` | `created_at = datetime.now()` is naive server-local time, and it is returned as an ISO string instead of epoch ms. | The response has `"created_at": "2026-...T10:00:00"`, but the contract requires an integer. | Store UTC now (ms precision) and serialize with `to_ms`. |
| 13 | `list_employees` L93 | `skip = page * page_size`: page 1 skips the first page. | `GET /employees` (page 1) is empty with fewer than 21 employees. | `(page - 1) * page_size`. |
| 14 | `list_employees` L94 | `total` counts the whole collection, ignoring the `department` filter (R10). | `?department=Sales` returns 2 items but `total` = 6. | `count_documents(q)` with the same filter. |
| 15 | `list_employees` L95 | No sort; the contract requires `emp_code` ascending. Without a stable order, pages overlap. | Order depends on insertion order / plan. | `.sort("emp_code", 1)` backed by an index. |
| 16 | `list_employees`, `list_attendance` (params) | `page` / `page_size` are unbounded. `page=0` gives a negative skip, so PyMongo raises and returns a 500. `page_size=100000` dumps the collection. | `GET /employees?page=0` returns 500. | `Query(ge=1)` and `Query(ge=1, le=100)`, which return 422. |
| 17 | `punch_in` L101 | Unknown employee: `emp` is `None`, so `emp["shift_start"]` raises `TypeError`. | `POST /attendance/punch-in {"emp_code":"EMP9999"}` returns 500 instead of 404. | Look up the employee first and return 404. |
| 18 | `punch_in` L102-103 | `datetime.fromtimestamp()` uses the server's local zone, so `date` is not the IST date (R1). The overnight rule is also missing. | On a UTC server, a punch at 02:00 IST is dated the previous day. A 00:30 punch on a 22:00 shift should be dated the previous day but is not. | `attendance_date()`: convert to IST and apply the overnight rule. |
| 19 | `punch_in` L104-118 | Check-then-insert with no unique index on `(emp_code, date)`, so it is not race-safe. | 15 parallel identical punch-ins return several 201s and leave duplicate documents. | Unique index `(emp_code, date)`; insert and map `DuplicateKeyError` to 409. |
| 20 | `punch_in` L119-121, `list_attendance` L148-149 | Returns `"id"` (the ObjectId), which the contract forbids. `punch_in` is returned as a datetime string instead of epoch ms. | The response has an `id` field and `"punch_in": "2026-07-06T04:35:00"`. | A single `record_out()` serializer: no `_id`/`id`, instants as epoch ms. |
| 21 | `list_attendance` L144-147 | Loads every matching document into Python, sorts and slices in memory, and has no index. | At 100k records each call reads the whole collection: slow, memory-heavy, a COLLSCAN. | `find(q).sort(...).skip().limit()` in MongoDB, with indexes; `count_documents` for `total`. |
| 22 | `list_attendance` L145 | Sorts by `date` only. The contract requires `date` desc, then `emp_code` asc. | Rows on the same date come back in arbitrary order and can repeat or disappear across pages. | `sort([("date", -1), ("emp_code", 1)])`. |
| 23 | `list_attendance` (params) | No validation: `date_from > date_to`, malformed dates and unknown statuses are accepted. | `?date_from=2026-07-07&date_to=2026-07-06` returns 200 (empty) instead of 422. `?status=FOO` returns 200. | Parse the dates (422 when invalid or reversed); `status` is the `Status` literal. |
| 24 | `list_attendance` L149 | Legacy records (sample #9) are returned without `history` / `half_day`, so required response fields are missing. | Sample #9 has no `half_day` key in the response. | `record_out` defaults: `history` → `[]`, `half_day` → `false`, minutes → `0`. |
| 25 | module (startup) | No indexes are created. The seeded DB only has `_id`. | Every query is a COLLSCAN, and uniqueness is never enforced. | `ensure_indexes()` at startup (idempotent `create_index`), with a background retry if Mongo is not up yet. |
| 26 | `punch_in` L102 | `if body.punched_at` is a truthiness test, so `0` silently means "now". | Hidden by #9 today; it bites as soon as validation changes. | `is not None`, and range validation rejects 0 anyway. |

## Looked at and decided were not defects
- **`load_dotenv()`** defaults to `override=False`, so real environment variables already take priority over `.env`. I kept it, made `override=False` explicit, and added a comment.
- **The `IST = timezone(timedelta(hours=5, minutes=30))` constant** is correct. IST has no DST.
- **Fallback `MONGO_URI` / `MONGO_DB` defaults** are fine for local development. The grader always injects its own values, and nothing secret is hard-coded.
- **Sync `def` endpoints with a global `MongoClient`.** FastAPI runs them in a thread pool, and `MongoClient` is thread-safe with its own pool. Concurrency correctness comes from unique indexes and conditional updates, not from the request model.
- **`compute_overtime` taking the record's `date`** as the base for the shift end is the right idea, because it uses the attendance date rather than the punch-out date. Only the overnight +1 day and the R3 minimum were missing.
- **`doc.pop("_id", None)` after `insert_one`** in `create_employee` is correct (PyMongo mutates the dict). The new code builds the response explicitly instead.
